# 04 — สรุปแผนและตอบรับ

## เป้าหมาย

ผลโหวตกลายเป็นแผนเดินทางที่เพื่อนตอบรับได้ และเมื่อแผนเปลี่ยนทุกคนรู้ว่าต้องตอบใหม่

## พฤติกรรม

- หลังหมดเวลาโหวต ผู้จัดเห็นจำนวนคน `available/maybe/unavailable` ของแต่ละวัน และคะแนนสถานที่ทั้งจากทุกคนและเฉพาะคนที่ว่างในวันที่กำลังเลือก
- ผู้จัดเลือกวันหนึ่งรายการและสถานที่หนึ่งรายการของทริปเดียวกัน ระบุทั้งเวลานัดพบและจุดนัดพบก่อนยืนยัน; ถ้าคนว่างหรือคนเลือกสถานที่นั้นน้อย หน้าเว็บเตือนแต่ผู้จัดยังตัดสินใจได้
- คำสั่งยืนยันตรวจผู้จัด, สถานะ `voting`, กำหนดปิดโหวต, ความเป็นเจ้าของตัวเลือก และค่าข้อมูลนัดพบอีกครั้ง แล้วเปลี่ยนเป็น `confirmed` ในธุรกรรมเดียว
- หลังยืนยัน ผู้ถูกชวนที่ไม่ปฏิเสธตอบ `going/maybe/not_going` ได้และแก้คำตอบได้; รายชื่อผู้ไปนับเฉพาะ `going` ของ `plan_version` ปัจจุบัน
- การเปลี่ยนวัน สถานที่ เวลานัดพบ หรือจุดนัดพบหลังยืนยันเพิ่ม `plan_version` และบันทึกเหตุการณ์; RSVP เดิมยังอยู่ในประวัติ แต่ UI แสดงว่า “ต้องตอบรับแผนใหม่”
- ผู้ถูกชวนที่เคยปฏิเสธสามารถกลับมาเข้าร่วมได้หากยังเป็นสมาชิกกลุ่ม แล้วตอบ RSVP ของแผนปัจจุบัน

## เกณฑ์ตรวจรับ

1. ผู้จัดยืนยันตัวเลือกจากอีกทริปหรือยืนยันก่อนหมดเวลาโหวตไม่ได้
2. หลังยืนยัน ผู้ร่วมทริปเห็นวัน สถานที่ และข้อมูลนัดพบชุดเดียวกัน
3. A และ B ตอบรับแยกกันได้; คนที่ยังไม่ตอบไม่ปรากฏในรายชื่อผู้ไป
4. เปลี่ยนแผนแล้วคำตอบ RSVP รุ่นก่อนยังตรวจย้อนหลังได้ แต่ไม่นับเป็นคำตอบปัจจุบัน

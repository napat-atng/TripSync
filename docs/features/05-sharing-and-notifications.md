# 05 — แชร์และแจ้งเตือนในเว็บ

## เป้าหมาย

ผู้จัดส่งข้อมูลที่ต้องทำต่อให้เพื่อนได้ง่าย และผู้ที่กลับเข้าเว็บเห็นการเปลี่ยนแปลงสำคัญ

## พฤติกรรม

- ปุ่มแชร์คัดลอกลิงก์ทริปและข้อความสั้นที่มีชื่อทริป สิ่งที่ต้องทำ กำหนดปิดโหวตหรือแผนที่ยืนยัน และลิงก์ ผู้จัดส่งผ่านแชตที่กลุ่มใช้อยู่เอง
- สร้าง `trip_events` สำหรับคำเชิญ เปิดโหวต ยืนยัน เปลี่ยนแผน และยกเลิก; หน้าแจ้งเตือนแสดงเฉพาะเหตุการณ์ของทริปที่ผู้ใช้เกี่ยวข้องและมีสถานะอ่าน/ยังไม่อ่าน
- เมื่อเปิดแดชบอร์ดหรือหน้าทริป ให้คำนวณจากเวลาปัจจุบันว่ากำลังใกล้ปิดโหวตและผู้ใช้นั้นยังไม่ตอบหรือไม่; ไม่ต้องใช้ cron เพื่อแสดงการเตือนในเว็บ
- การเปลี่ยนแผนต้องแสดงข้อความ “ต้องตอบรับใหม่” บนหน้าทริปจนกว่าผู้ใช้นั้นจะตอบ RSVP ของ `plan_version` ปัจจุบัน
- MVP ไม่มีอีเมล, push notification หรือข้อความส่งอัตโนมัติไปแชตภายนอก ข้อความคัดลอกทำหน้าที่ช่วยผู้จัดเตือนเพื่อน

## เกณฑ์ตรวจรับ

1. ผู้จัดคัดลอกข้อความเชิญได้ก่อนโหวตและคัดลอกข้อความสรุปได้หลังยืนยัน โดยลิงก์เปิดหน้าทริปที่ถูกต้อง
2. ผู้ใช้ที่ไม่เกี่ยวข้องกับทริปไม่เห็นเหตุการณ์หรือแจ้งเตือนของทริปนั้น
3. เมื่อใกล้หมดเวลา ผู้ที่ยังไม่ตอบเห็นสิ่งที่ต้องทำในเว็บ; ผู้ที่ตอบครบแล้วไม่ถูกเตือนให้โหวตซ้ำ
4. เมื่อแผนเปลี่ยน ผู้ร่วมทริปเห็นว่าต้องตอบรับใหม่ แม้เคยตอบ `going` ไปแล้ว

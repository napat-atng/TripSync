# 03 — ตัวเลือกและการโหวต

## เป้าหมาย

ทุกคนบอกวันว่างและสถานที่ที่ชอบได้อย่างชัดเจน โดยผลรวมแยก “ไม่สะดวก” ออกจาก “ยังไม่ตอบ”

## พฤติกรรม

- ใน `draft` ผู้ถูกชวนที่ไม่ปฏิเสธเสนอวันและสถานที่ได้ ผู้จัดแก้/ลบตัวเลือกและเปิดโหวตเมื่อมีอย่างน้อยหนึ่งตัวเลือกของแต่ละประเภท
- เมื่อเปิดโหวต ระบบล็อกชุดตัวเลือกจนจบการโหวต หากต้องเปลี่ยนตัวเลือกให้ยกเลิกรอบโหวตและเริ่มทริปใหม่ใน MVP เพื่อไม่ให้คำตอบเดิมตีความผิด
- สำหรับวัน ผู้ใช้ตอบ `available`, `maybe` หรือ `unavailable` ให้ทุกตัวเลือกแล้วกดส่งหนึ่งครั้ง; แก้และส่งใหม่ได้ก่อนหมดเวลา
- สำหรับสถานที่ ผู้ใช้เลือกได้หลายแห่ง หรือเลือก “ไม่มีที่ที่ต้องการ” แล้วกดส่ง; การส่งโดยไม่เลือกมีความหมายต่างจากยังไม่ตอบ
- `vote_submissions` เก็บว่าผู้ใช้ส่งคำตอบวันและสถานที่แล้วหรือยัง ผลรวมและรายชื่อผู้ยังไม่ตอบแสดงแยกสองประเภท
- วันแสดงจำนวน `available` และ `maybe` แยกกัน ไม่รวม `maybe` เป็นคะแนนเต็ม สถานที่แสดงจำนวนคนเลือกทั้งหมด และเมื่อผู้จัดพิจารณาวันใด ให้แสดงจำนวนผู้เลือกสถานที่นั้นในกลุ่มที่ `available` ของวันดังกล่าว
- การส่งคำตอบวันหรือสถานที่แทนคำตอบเดิมทั้งชุดในธุรกรรมเดียว ภายใต้ข้อบังคับหนึ่งคนต่อหนึ่งตัวเลือก และตรวจสมาชิก/สถานะ/กำหนดเวลาที่เซิร์ฟเวอร์ทุกครั้ง; ผลรวมไม่นับคนที่ถูกนำออกจากกลุ่มหรือปฏิเสธทริป
- หลัง `vote_deadline` หน้าแสดง “รอผู้จัดสรุป” และ API ปฏิเสธคำตอบใหม่โดยไม่ต้องพึ่งงานตามเวลา

## เกณฑ์ตรวจรับ

1. ผู้ใช้ตอบทุกวันเป็น `unavailable` ยังนับว่า “ตอบวันแล้ว”; ผู้ใช้ที่ไม่เปิดหน้าทริปยังนับว่า “ยังไม่ตอบ”
2. ผู้ใช้ส่งสถานที่เป็น “ไม่มีที่ที่ต้องการ” ยังนับว่า “ตอบสถานที่แล้ว” และไม่เพิ่มคะแนนสถานที่ใด
3. ผู้ใช้แก้คำตอบก่อนกำหนดแล้วผลรวมเปลี่ยนตามคำตอบล่าสุด โดยไม่เพิ่มจำนวนผู้ตอบซ้ำ
4. ผู้ที่เปิดหน้าไว้ก่อนหมดเวลาแต่กดส่งหลังหมดเวลาบันทึกคะแนนไม่ได้
